# 滿版響應式版面設計

## 目標

移除寬螢幕手機上由固定 393px 外殼造成的左右灰色留白，同時保留像素插圖的比例與清晰度。小螢幕上不縮小字體、按鈕或輸入元件，只讓裝飾插圖在必要時等比縮小，內容卡片則依可用寬度自然收窄。

## 響應式策略

- 頁面背景與底部導覽列使用完整 viewport 寬度，不再受 393px 外殼上限限制。
- 393px 作為插圖與主要內容的設計基準寬度，而不是整個應用程式的最大寬度。
- 螢幕寬度大於或等於 393px 時，插圖維持原始設計尺寸並置中，不向上放大。
- 螢幕寬度小於 393px 時，裝飾插圖舞台依可用寬度等比縮小，避免左右裁切。
- 插圖舞台以 width: min(100%, 393px)、aspect-ratio 與百分比座標縮放，不使用 Android 瀏覽器相容性不足的 CSS 除法。
- 字體、按鈕、核取方塊、輸入框與底部導覽不參與插圖縮放，維持既有可讀性與點擊尺寸。
- 卡片與對話框保留目前的最大寬度，但使用 `width: 100%` 與安全的左右內距，在窄螢幕自然收窄。
- 平板與電腦延伸背景，主要內容仍維持手機手冊的閱讀寬度並置中。

## 首頁

- Hero 的底色延伸至整個畫面寬度。
- 樹、車、山、雲等裝飾物放在置中的 393px 插圖舞台內；窄於 393px 時整個舞台等比縮小。
- 標題與日期不跟著插圖舞台縮放，維持既有字級與可讀性。
- 內容區的紙張底色與點狀紋理延伸至完整寬度。
- 行前檢查卡、活動卡、狀態卡與對話框保留既有最大寬度，置中並允許在窄螢幕縮窄。

## 行程與背包

- 頁面底色延伸至完整 viewport 寬度。
- 行程時間軸、行程卡與背包內容維持最多 393px 的閱讀區並置中。
- 像素物品、人物與裝飾素材不因寬螢幕而放大。
- 窄螢幕所需的收縮由容器與卡片寬度處理，不縮小文字。

## 底部導覽與 Bottom Sheet

- 底部導覽列橫跨 viewport，三個導覽項目平均分配寬度。
- 圖示與文字維持既有尺寸，不跟著螢幕放大或縮小。
- Bottom Sheet 維持手機閱讀寬度並置中；在窄螢幕不得超出 viewport。

## 色彩模式

- 延續現有的固定淺色模式設定。
- 本次只調整寬度、定位與響應式行為，不改變既有配色與字體尺寸。

## 驗證

- CSS 測試確認應用外殼與底部導覽不再使用 393px 最大寬度。
- CSS 測試確認插圖舞台只在小於 393px 時縮小，且不會在較大螢幕放大。
- CSS 測試確認插圖舞台不使用 CSS 除法；景物尺寸與位置由比例座標取得。
- CSS 測試確認主要卡片具有既有最大寬度與可縮小寬度。
- CSS 測試確認既有標題、內文與導覽字級沒有被響應式規則覆寫。
- 執行完整測試、lint 與正式建置，確認其他互動與資料功能不受影響。

## 不在範圍內

- 不重新設計像素素材或提高其解析度。
- 不調整文案、行程資料與互動流程。
- 不讓插圖在寬螢幕上放大填滿空間。
- 不在本次修改完成後自動部署；部署需另行確認。
